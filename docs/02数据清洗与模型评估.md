# 02 数据清洗与模型评估

本文解释已实现的数据处理及实际评估结果，不是运行操作手册或老师提交材料。证据批次：`20260914T120724782833Z`，核对日期：2026-09-14。实现依据为 `jobs/pipeline.py`、`jobs/forecast.py`，数值依据为同批次 ADS 与 `data/reports/20260914T120724782833Z-quality.json`。

## 1. 清洗流程与真实处理量

原始 CSV 先复制到按批次隔离的 ODS 并计算 SHA-256，再由 Spark 以表头模式读取，CSV 结构错误使用 FAILFAST。会话先按全字段去重、再去首尾空格；数值字段转换、日期规范化后隔离无效记录及主键冲突，最后关联站点、派生维度并写入 DWD。去重发生在 trim 之前，不能声称已先完成所有文本规范化再去重。

本次清洗前后都是3395条会话、105条站点和1594条电池记录。零删除不表示没有清洗：本批次全部会话执行了年份规范化，并完成类型转换、关联检查与异常标记。电池记录保留在 `telemetry_unverified`，保留行数不表示质量已合格。

| 规则 | 本批次影响数 | 实际处理与解释 |
| --- | ---: | --- |
| R01 完全重复会话 | 0 | 全字段一致才去重；不同内容的同 ID 不任意择一 |
| R02 年份0014/0015规范化 | 3395 | 将年份解释为2014/2015，保留 `created_raw`、`ended_raw`，并用星期、小时、时长交叉校验 |
| R03 关键字段与主键冲突 | 0 | 关键字段缺失、转换失败、负电量、非正时长、负费用、结束早于开始等隔离到 `rejected`；冲突 ID 的记录整组排除 |
| R04 日期衍生字段不一致 | 0 | 时长差超过1分钟、星期或起止小时不一致则停止发布；代码不是只警告后继续 |
| R05 零电量会话 | 55 | 保留，计入次数，电量贡献为0 |
| R06 零费用会话 | 3016 | 保留，不插补价格、不假定免费原因 |
| R07 连接时长超过24小时 | 1 | 保留并设置 `long_session`；不能据此认定连续充电超过24小时 |
| R08 站点关联缺失或口径冲突 | 0 | 站点键必须唯一；关联后名称缺失或位置、设施冲突则停止发布 |
| R09 时长 IQR 候选异常 | 59 | 仅统计并公开阈值，不凭统计离群删除真实会话 |
| R10 电池采样时间精度丢失 | 1594 | 原始 `record_time` 仅一个不同文本值，保留原文，不恢复伪造时间或画连续充电曲线 |
| R11 无电池记录的会话 | 1801 | 用会话 ID 与 `esd` 左反关联计数，不补造电池样本 |
| R12 电池单位、符号待确认 | 1594 | 不将负电流直接判错，单位含义不明的字段排除出核心指标和预测 |

各规则可能重叠，不能累加为“总异常记录数”。R12 表示整份电池表需要语义确认，不表示每个单元格均已证实错误。R11 是会话级计数，不证明电池表满足逐会话一对一采样。

时长 IQR 使用 `approxQuantile`，相对误差参数0.001。本批次 Q1=2.108888889 h，Q3=3.543055556 h，下界=-0.0423611115 h，上界=5.6943055565 h。59条落在界外的会话仍参与聚合及每日模型目标。规则文本虽提到模型评估，但目前没有“删除离群会话前后模型效果”的单独敏感性实验，不能声称已做该对比。

日期年份解释只得到文件内部一致性的支持，没有外部采集记录证明。代码中的比较、空值与类型校验不应扩大成覆盖任意恶意或损坏输入的证明，例如所有衍生字段空值、所有非有限数值的逐项隔离仍需专门测试。当前数据的规则计数为0，只能说明本批次没有被对应检查发现的问题。

## 2. 发布前的核对

程序检查十个单维度的次数与电量是否回到总 KPI。本次文档工作从 ADS 独立求和，十维次数均为3395，电量均为19723.69 kWh（允许二进制浮点尾差）；另复核站点×小时和平台×日类型的会话总数各为3395，散点数为3395。

代码的行数保护是“清洗后行数加隔离记录不同 ID 数不能超过原始行数”的上界检查，不是完整逐行流转账本。故不能把它描述为适用于任意重复、冲突和无效组合的严格等式守恒。当前批次去重及隔离均为0，清洗前后会话行数相等有实际数据支持。

JSON 发布禁止 NaN/Infinity，先写临时文件再替换单个目标文件；批次 ADS、最新 ADS 和质量报告依次写入，不是跨所有文件的一次原子事务。MySQL 发布事务另见《01技术选型与数据口径》。

## 3. 预测目标、补日与特征

目标为“按会话开始日期汇总的数据集记录电量（kWh）”。跨日会话不分摊，目标不是逐时负荷、瞬时功率、站点占用率或当前现实运营需求。

原始聚合有238个有记录日期。模型从2014-11-18到2015-10-04补齐321个自然日，其中83个无记录日期填0；填0仅表示提供文件无记录，不能断言现实需求为0。舍去缺少7日滞后特征的前7天后，得到314个建模样本。

| 特征 | 定义 | 预测当天能否获得 |
| --- | --- | --- |
| `lag1` | 前一天记录电量 | 以前一天已经完整入库为条件 |
| `lag7` | 前7天对应日期的记录电量 | 是；也是同星期基线的预测值 |
| `mean7` | 前7天的平均电量，窗口为[-7,-1] | 是，不含当天目标 |
| `weekday_n` | Spark 星期编号，周日=1、周六=7 | 是 |
| `month` | 月份数值 | 是 |
| `trend` | 距数据起始日期的天数 | 是 |

费用、电池采样字段、当天结束后才能知道的目标电量不进入特征。星期和月份按数值使用，当前没有独热编码或周期正余弦编码，这是简化建模选择，不是已经优化完成的结论。

## 4. 时间切分和选择规则

| 集合 | 日期范围 | 样本数 | 用途 |
| --- | --- | ---: | --- |
| 训练集 | 2014-11-25—2015-07-01 | 219 | 拟合候选模型 |
| 验证集 | 2015-07-02—2015-08-17 | 47 | 按 RMSE 最小选择模型，包括基线 |
| 测试集 | 2015-08-18—2015-10-04 | 48 | 报告所选模型及全部候选的最终对比 |

按日期排序，以样本数70%和85%的整数截点划分，没有随机打乱。候选为同星期历史基线、线性回归及随机森林。线性回归参数为 `regParam=0.1`、`elasticNetParam=0`、`maxIter=60`；随机森林为32棵树、最大深度5、种子20260914。机器学习模型的负预测截断为0，验证、测试和次日预测都使用此规则。

训练后的评估模型参数保持固定。测试特征使用此前已观察日的真实电量，包括更早测试日的实际值；因此是“每天获得前日真实数据后进行单步预测”的滚动单步评估，不是从测试起点一次预测48天，也不是每天重新训练。代码不使用测试 RMSE 选择模型，但不能据此声称完成了多轮时间交叉验证或广泛调参。

## 5. 真实评估结果

以下来自 ADS 的 `model.metrics` 与 `model.validation_metrics`，仅为排版保留四位小数。

| 模型 | 验证 RMSE | 测试 MAE | 测试 RMSE | 测试 R² |
| --- | ---: | ---: | ---: | ---: |
| 同星期历史基线 | 43.1754 | 32.6217 | 47.6504 | 0.7122 |
| 线性回归（选用） | 42.2457 | 33.7782 | 45.1512 | 0.7416 |
| 随机森林 | 67.6093 | 75.1494 | 88.2758 | 0.0124 |

MAE 是绝对误差均值，RMSE 是平方误差均值开方，二者单位均为 kWh；R² 无量纲，不能写成“74.16%预测准确率”。线性回归按最小验证 RMSE 被选中，测试 RMSE 相对基线下降约5.24%，但测试 MAE 从32.6217增加到33.7782。可以说对较大误差更敏感的 RMSE 有改善，不能说所有指标均优于基线。随机森林本次表现明显更差，复杂模型不保证更好。

模型目录中保存的是利用全部可用特征样本重新拟合的两个机器学习模型，服务于历史末日后的次日预测；它们不是生成上表测试指标时仅用训练集拟合的模型。不要拿全量重训模型回测同一测试集，再把结果替换成独立测试效果。

本批次选中线性回归对2015-10-05的预测为165.33716708779744 kWh，展示约165.34 kWh。这是教学历史数据末尾的次日估计，不是2026年的预测；该日缺少实际值，不能判定预测成功。输出没有预测区间，也没有给出不确定性覆盖率。

## 6. 结论适用范围与待验证事项

当前证据支持本批次本地 Spark 清洗、聚合、训练、验证选择和48天单步测试产物已形成。以下事项没有完成证明：多时间窗稳定性、模型误差显著性、长期多步预测、缺日置零敏感性、离群会话保留策略敏感性、当前真实运营外推、跨设备业务时区确认，以及全量重训模型重新加载后的预测一致性。

模型有时间趋势特征，日历编码也较简化；数据仅覆盖不到一年且测试只有48天。现有点估计和一次切分不足以证明季节泛化能力或生产可用性。数据来源真实性、费用币种、设施/车辆编码字典和电池字段单位仍需来源方说明。
