# 01 技术选型与数据口径

本文为项目内部技术说明，不是老师提交材料，也不包含安装、启动和完整操作教程。核对日期：2026-09-14。数值依据 `data/ads/20260914T120724782833Z/dashboard.json`，对应当前 `data/ads/dashboard.json` 的批次 `20260914T120724782833Z`。后续重跑应重新核对批次，不能直接沿用本次验收结论。

## 1. 系统实际分工

主业务链为：提供的 CSV → Windows 本地 Spark 清洗、关联、聚合和建模 → Parquet 与 ADS JSON → 显式导入 MySQL → Flask 只读接口 → Vue 可视化。Ubuntu HDFS 通过 WebHDFS 保存及回读文件，是独立存储验证链；当前 Spark 默认 `local[2]`，不能描述成 YARN 集群计算或 Spark 原生 HDFS RPC 读写。

| 组件 | 当前实现与选型理由 | 证据和边界 |
| --- | --- | --- |
| Python、PySpark、Java | 当前协作环境为 Python 3.13.15、PySpark 4.2.0、Java 17；Spark 统一完成清洗、聚合和 MLlib 模型 | `requirements.txt` 固定 PySpark 4.2.0，ADS 记录同版本；Python/Java 完整运行情况由主任务提供，本次文档工作未重新启动 Spark |
| Windows junction | `D:/workspace/runtime/bigdata-python` 为 Junction，启动器通过英文运行时路径定位 Python 和 Spark | `jobs/runtime.py` 配置英文启动路径，绕开 `.cmd` 启动链中的中文路径编码问题；业务项目仍可保持中文目录 |
| Parquet、JSON | DWD 明细用 Parquet，ADS 聚合、质量及模型结果用 JSON | 按批次保留历史结果；文件存在不等于所有系统均使用最新批次 |
| Hadoop HDFS | Ubuntu 单节点 HDFS 保存原始输入及分析产物，上传后回读并比较 SHA-256 | `deploy/hdfs_sync.py`；Windows 的 Hadoop 3.3.0 本地辅助路径与虚拟机 Hadoop 3.2.1 分属不同环境，不能混写版本 |
| MySQL、Flask | MySQL 保存版本化结果，Flask 提供统一只读契约 | `api/db.py`、`api/import_results.py`、`api/__init__.py`；API 不在读取时跑 Spark，也不回退读取本地 JSON |
| Vue、JavaScript、Vite | Vue 3.5.21、JavaScript 单文件组件、Vite 6.3.6 | `frontend/package.json` 和 `src/App.vue`；本项目业务源码不是 TypeScript 项目 |
| DataV、ECharts | DataV 提供可视化容器，ECharts 5.6.0 绘制统计图表 | DataV 实际依赖为 `@dataview/datav-vue3`，锁定 `0.0.0-test.1672506674342`；`App.vue` 按需引入 `BorderBox1` |
| Hive、Flume、Flink | 未进入当前主链 | 不据环境中存在软件就声称已集成、已采集或已实现流处理 |

老师指定的 [DataV Vue3 指南](https://datav-vue3.jiaminghi.com/guide/) 明确对应 `@dataview/datav-vue3`，与本项目包名一致。该指南将组件库标为 Alpha，统计图表主要由本项目的 ECharts 实现；不能把所有图表都说成 DataV 原生图表。

## 2. 来源、分层与可追溯性

三个文件来自同一份教学数据来源，不是三个独立采集渠道。读取 ODS 副本即可复核输入，本说明不要求修改原始数据。

| 输入文件 | 数据粒度 | 本批次行数 | 用途 |
| --- | --- | ---: | --- |
| `nvv2t.csv` | 充电会话，键 `sessionId` | 3395 | 核心指标、十维分析、交叉分析与每日预测目标 |
| `nvv2t_md_end.csv` | 站点，键 `stationId` | 105 | 站点名称、地址、位置与设施类型关联核验 |
| `dsv13r2.csv` | 电池记录，使用 `esd` 关联会话 | 1594 | 保留并报告质量问题；不进入核心电量或预测特征 |

ODS 为 `data/ods/<run_id>/` 的原始副本；DWD 为 `data/dwd/<run_id>/` 下的 `sessions`、`stations`、`rejected`、`telemetry_unverified`。ADS 为 `data/ads/<run_id>/dashboard.json`，另有最新文件 `data/ads/dashboard.json`；质量报告位于 `data/reports/`，模型位于 `data/models/<run_id>/`。目前没有独立落盘的 DWS 层，不把内存聚合包装成已建成的 DWS 数仓。

ADS 的 `meta.source_sha256` 保存三份输入的 SHA-256；它能证明文件身份，不能证明采集准确性、测量仪器有效性或来源授权情况。HDFS 回读校验同样只证明传输后的字节一致。

## 3. 核心指标定义

统计范围为规范化后的会话开始日期 2014-11-18 至 2015-10-04。Spark 会话时区固定 UTC；原始时间的真实业务时区未获外部确认，因此不要另行解释为北京时间或宣称已完成时区校正。跨日会话的全部电量归入开始日期，不拆分到实际充电发生的各日。

| KPI | 计算口径 | 本批次值 | 解释限制 |
| --- | --- | ---: | --- |
| `sessions` | 清洗后会话行数 | 3395 | 零电量会话仍计数；不是并发连接数 |
| `energy_kwh` | `sum(kwhTotal)`，发布时四舍五入至四位小数 | 19723.69 kWh | 使用会话电量，不使用单位不明的电池字段 |
| `stations` | 会话中不同 `station_id` 数量 | 105 | 是本数据覆盖站点数，不代表目前在线站点数 |
| `users` | 不同 `userId` 数量 | 85 | 是标识符去重数，不保证对应85名自然人 |
| `avg_duration_h` | 会话 `chargeTimeHrs` 算术平均 | 2.841487645227099 h | 连接时长不等于持续通电时长；总平均不能直接平均各组平均值 |
| `fees` | `charging_fees` 转 `decimal(14,4)` 后求和 | 401.52 | 币种未知；不写人民币符号，不推导营业收入或单价 |

第二次运行已在 ADS 中呈现 `19723.69`，修正旧 KPI 浮点尾数展示。电量仍以 double 计算，JSON 中不保留固定小数位；分组值再次相加仍可能有约 `1e-11` 的二进制尾差。代码对十维电量合计使用绝对差不超过 0.1 kWh 的发布校验，不能称为所有计算均使用精确十进制。前端展示另行取小数位，例如 KPI 电量显示一位小数。

## 4. 十个维度与两个交叉分析

下表各维度均来自同一清洗会话集合，每组包含 `sessions`、`energy_kwh`、`avg_duration_h`。本次独立复核十维会话数均合计3395、电量均在浮点容差内合计19723.69 kWh。

| 维度 | ADS 数组 | 分组键或口径 | 本批次数组行数 |
| --- | --- | --- | ---: |
| 日期 | `daily` | `created` 衍生 `date`，只包含有记录日期 | 238 |
| 小时 | `hourly` | 会话开始小时 `hour` | 23 |
| 星期 | `weekday` | 经日期一致性校验的原始星期字段 | 7 |
| 站点 | `stations` | `station_id`、`name` | 105 |
| 位置 | `locations` | 原 `locationId` 与站点地址，输出 `location_id`、`name` | 25 |
| 设施类型 | `facility` | 原 `facilityType`，输出 `facility_type` | 4 |
| 平台 | `platform` | 去首尾空格并统一小写 | 3 |
| 车辆管理属性 | `vehicle` | 原 `managerVehicle`，输出 `manager_vehicle` | 2 |
| 用户 | `users` | `userId`，输出 `user_id` | 85 |
| 连接时长区间 | `duration` | `[0,1)`、`[1,2)`、`[2,4)`、`[4,8)`、`[8,+∞)` 小时 | 5 |

两个交叉分析为 `station_hour`（站点×开始小时，705组）和 `platform_daytype`（平台×工作日/周末，提供次数及单次平均电量）。这里的“工作日”仅表示周一至周五，没有法定节假日或调休日历。两者会话数各合计3395；`avg_energy_kwh` 不能直接求和当作总电量。

`energy_duration` 另提供3395个会话散点，用于连接时长与电量的关系观察，不重复凑入“十维+两交叉”。前端排名取 Top 10 或 Top 12，不能把截断后的图表当作全量守恒检验。小时数组实际只有23组，页面标题“24小时”并不代表后端补齐了24个桶；缺失桶不应凭空解释为真实无需求。设施编码与车辆属性编码缺少字典，不推测商业含义。

## 5. 服务契约与发布边界

`/api/dashboard` 返回 `{meta,kpis,charts,quality,model}`；`/api/quality` 与 `/api/model` 分别返回对应对象，`/api/health` 检查数据库及活动版本。默认 Flask 监听127.0.0.1:5000，数据库配置默认使用独立3307端口。

MySQL 中 `dashboard_runs` 保存四段 JSON 和导入摘要，`dashboard_charts` 保存图表数组，`dashboard_active` 指向活动版本。导入版本及活动指针在同一事务提交；API 在 REPEATABLE READ 事务内读取。数据库导入 UUID 与 Spark 的 `meta.run_id` 是两个不同标识，前者标识导入版本，后者标识计算批次。

当前服务是全量快照，不支持日期筛选；数据接口遇到 `start`/`end` 返回400，其他查询参数同样拒绝。数据库不可用或无结果返回503。更新本地 ADS 不会自动更新 MySQL；必须核对导入后接口中的 Spark 批次才能确认刷新生效。运行状态和端到端验收结论见《03需求与验收矩阵》。
