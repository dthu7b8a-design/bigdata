# 从打开项目到运行、调试和审核

本手册对应这台电脑上的项目。现在是**开发成果审核阶段**，还没有开始制作`第二阶段项目-大数据部分`中的老师提交材料。

## 1. 先认识三个程序

- **PyCharm**：打开、编辑、运行Python代码，也可以在其Terminal里运行前端命令。项目名称仍叫bigdata。
- **浏览器**：查看大屏。直接打开`.vue`或`index.html`源码不能获得完整功能。
- **VMware中的Ubuntu**：提供Hadoop HDFS存储。普通本地大屏演示读取MySQL中已发布的分析结果，开网页时不必每次重跑Spark或Hadoop。演示HDFS链路时必须运行虚拟机。

代码路径：`D:\workspace\第二阶段\bigdata`。老师数据路径：`D:\workspace\第二阶段\04.数据集最终版`。第一阶段原项目仍位于`D:\workspace\第一阶段\evchargeplatform`。

## 2. 打开已有PyCharm项目

1. 打开PyCharm。
2. 如果显示欢迎页，点击Open；如果已经打开其他工程，选择File → Open。
3. 选择`D:\workspace\第二阶段\bigdata`整个文件夹，点击Open。
4. 如果询问在当前窗口还是新窗口打开，可选New Window，便于保留别的项目。
5. 左侧Project面板应看到`api`、`jobs`、`frontend`、`data`、`deploy`、`scripts`等目录。

## 3. 核对解释器和环境

1. 在Settings中搜索Python Interpreter。
2. 项目解释器应指向`D:\workspace\第二阶段\bigdata\.venv\Scripts\python.exe`，版本3.13.15。
3. 如果没有选中，选择Add Interpreter → Add Local Interpreter → Existing，选中上述文件。
4. 打开底部Terminal；看不到时通过View → Tool Windows → Terminal打开。
5. 本文命令使用PowerShell。如果终端是cmd，在终端设置中选择PowerShell，或先输入`powershell`。
6. 粘贴以下命令，按Enter执行：

```powershell
cd 'D:\workspace\第二阶段\bigdata'
& .\.venv\Scripts\python.exe --version
& .\.venv\Scripts\python.exe -m pip show pyspark flask numpy pymysql
& 'D:\node\node.exe' --version
& 'D:\workspace\jdk-17\bin\java.exe' -version
```

期望：Python3.13、PySpark4.2、Flask3.1、Node24、Java17。Python3.13已经通过本项目的实际Spark和ML运行，不必为本项目另装3.11/3.12。

`JAVA_HOME`指向Java安装根目录，`HADOOP_HOME`指向Hadoop安装根目录，均不要加到`bin`末尾。它们不是存放业务数据的目录，也不会自行启动服务器。

Spark在Windows的`.cmd`启动过程中对中文路径处理有问题，所以已有英文入口`D:\workspace\runtime\bigdata-python`指向同一个`.venv`。`jobs/runtime.py`会使用它设置Spark类路径和Python工作进程路径。**不要删除这个入口，也不要认为存在两套独立环境。**

## 4. 最快打开已经构建好的大屏

## 5. 在页面上依次审核什么

1. **运行总览**：查看累计会话、总电量、站点、用户、平均连接时长、原始费用，以及时序和站点表现。
2. 检查总会话3395、站点105、用户85、电量约19723.69 kWh；费用401.52没有人民币符号。
3. 将鼠标放在图形上，查看悬浮信息。
4. **多维分析**：查看日期、时段、星期、站点、地点、设施类型、平台、车辆标记、用户和连接时长等维度。
5. 查看“站点×时段”热力图及“平台×工作日/周末”比较。切换会话数/电量等实际支持的指标，观察图表变化。
6. **质量与预测**：阅读清洗前后记录数、12条规则、异常处理说明，再看模型指标和预测曲线。
7. 模型不是保证精确的答案：线性回归、随机森林和同星期基线的实际成绩都会展示，测试集没有参与模型选择。
8. 点击刷新按钮，页面重新从Flask/MySQL读取最新发布结果。刷新页面不等于重新采集设备数据或重新训练模型。
9. 大屏暂时以全量历史统计为口径，没有伪造日期筛选功能。页首的日期范围为说明文字。

## 7. 在PyCharm逐步调试Python

1. 展开`jobs`，打开`pipeline.py`。`run()`负责读取数据、清洗、检查、聚合和发布本地结果。
2. 在某行左侧行号旁单击，出现红点即设置断点。建议先在`before=...`之后或`payload=...`处断点。
3. 从右上角运行配置选择`02 Spark Clean Analyze Train`，点击Debug（虫子图标）。如未自动识别，选择Add Configuration → Python，运行方式选Module name，填写`jobs.pipeline`，Working directory选择bigdata根目录。
4. 断点停下后，在Variables查看Python变量；Spark DataFrame本身是计算计划，数据未必已全部计算。
5. Debug Console中可输入`df.printSchema()`或`df.limit(5).show(truncate=False)`检查字段与样例。`count()`、`show()`会实际触发Spark作业，需等它完成。
6. Step Over执行当前行；Resume继续到下一个断点；红色Stop结束调试。不要在同一个数据输出批次同时启动多个调试任务。
7. `forecast.py`中可查看特征、训练/验证/测试分段和模型评估。改变特征后需重跑，再导入MySQL。
8. 调试Flask时先停止脚本启动的5000端口服务，选择`01 Web Flask`或右键`main.py` → Debug。
9. 在`api/__init__.py`对应接口处设置断点，再由浏览器访问`http://127.0.0.1:5000/api/dashboard`触发。断点暂停期间浏览器可能等待或超时，这是调试暂停导致的。

## 9. 运行Hadoop/HDFS存储演示

1. 打开VMware，启动已有Ubuntu虚拟机并登录。
   已修复Ubuntu NetworkManager持久关闭网络的问题，并保存有线连接自动连接配置；整机重启复测尚未进行。HDFS服务仍可能在重启后停止。在Windows的PyCharm Terminal里运行下面的一键准备命令，可检查恢复网络并启动已有HDFS：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start_hdfs.ps1
```

   它复用本机已有VMware连接配置，不格式化HDFS。HDFS首次启动和安全模式等待可能需要几分钟，请等待结果，不要重复启动。运行报告在`runtime/hdfs-start.log`；若换电脑或移动了历史连接配置，需要按`deploy/README.md`更新连接方式。
2. 在Ubuntu中打开Terminal，执行：

```bash
source /etc/profile.d/hadoop.sh
jps
hdfs dfsadmin -report
```

3. 如果已有NameNode、DataNode、SecondaryNameNode且报告有Live datanodes，直接继续。若服务停止，执行`start-dfs.sh`，然后重新检查。
4. **不要执行`hdfs namenode -format`。** 这不是启动命令，已有HDFS不需要重新初始化。
5. `hostname -I`查看Ubuntu地址，本次配置地址为`192.168.203.128`。若地址变化，下面命令的endpoint需要替换。
6. 在Windows浏览器打开`http://192.168.203.128:9870`查看NameNode管理页。
7. 回到Windows PyCharm的bigdata根目录Terminal，把项目数据同步至HDFS并读回校验：

```powershell
& .\.venv\Scripts\python.exe .\deploy\hdfs_sync.py --endpoint 'http://192.168.203.128:9870' sync --source .\data --remote /evcharge-stage2 --overwrite
```

8. `--overwrite`只用于更新该项目远端同名结果，脚本不会删除HDFS其他目录。每个文件上传或跳过后都会下载并比对SHA-256。
9. 在Ubuntu查看数据层：

```bash
hdfs dfs -ls /evcharge-stage2
hdfs dfs -ls /evcharge-stage2/ods
hdfs dfs -ls /evcharge-stage2/dwd
hdfs dfs -cat /evcharge-stage2/ads/dashboard.json | head -c 500
```

10. 在Windows实际下载最新结果：

```powershell
& .\.venv\Scripts\python.exe .\deploy\hdfs_sync.py get --remote /evcharge-stage2/ads/dashboard.json --output .\runtime\hdfs-dashboard.json
Get-FileHash .\runtime\hdfs-dashboard.json
Get-FileHash .\data\ads\dashboard.json
```

两者SHA-256应相同。这样证明数据真实存在于HDFS且能够读回，不是只把“Hadoop”写在页面标题上。

11. 若要演示“真正从HDFS原始数据开始，再进行清洗分析与模型训练”，在项目根目录执行：

```powershell
& .\.venv\Scripts\python.exe .\deploy\hdfs_pipeline_demo.py --remote-source /evcharge-stage2/ods --baseline .\data\ads\dashboard.json
```

程序从HDFS下载3份原始CSV，验证来源哈希，再调用同一Spark任务。产物写在`deploy/hdfs-demo/时间戳/output`，不会覆盖正式数据。结束查看同目录`comparison.json`，`passed: true`表示会话指标、图表、质量报告和模型结果与本地原始数据处理结果一致。时间戳和批次号不同是正常现象。

当前部署是本机Spark计算、Ubuntu HDFS存储，通过WebHDFS传输。它不是在YARN上分布式训练；不要在答辩时把这两者混为一谈。

## 11. 停止与下次启动

- 用`scripts/start.ps1`启动：执行`scripts/stop.ps1`停止该脚本记录的Flask进程。
- 用PyCharm Run/Debug启动：点击对应运行窗口的红色Stop。
- 用前台终端启动Flask或Vite：在对应终端按Ctrl+C。
- MySQL独立实例可保持运行；需要停止方法见API文档。不要结束其他项目的MySQL服务。
- Ubuntu终端执行`stop-dfs.sh`可停止这台单机HDFS。普通大屏读取已存MySQL结果，不会因此抹掉分析数据。
- 下次只看大屏，执行第4节；需要演示HDFS，再启动虚拟机并执行第9节检查。

## 12. 常见问题怎么判断

| 现象 | 排查与处理 |
|---|---|
| `No module named flask/pyspark` | 用明确的`.venv\Scripts\python.exe`执行；核对PyCharm解释器，而不是全局pip |
| `SparkSubmit`找不到、`JAVA_GATEWAY_EXITED` | 检查英文runtime入口、JDK17和`jobs/runtime.py`；不要先删项目或换Python |
| Java库提示找不到`libopenblas.dll` | 本次已验证可回退实现并完成训练；结合最终退出码和结果判断，不把提示本身当失败 |
| 5000端口被占用 | 先关闭本项目旧Flask运行窗口；不要随意结束不认识的进程 |
| `/api/health`为503 | 查独立MySQL3307是否启动、`api/.env`是否存在、是否执行过导入 |
| 页面显示旧批次 | Spark结束后执行`api.import_results`，再点击页面刷新 |
| 改了Vue但5000页面不变 | 正式页面读取`frontend/dist`；执行`npm run build`，或在5173开发页调试 |
| 5173有页面但接口失败 | Flask5000还需运行；查看F12 Network和Vite代理配置 |
| HDFS连接超时 | 查看虚拟机网卡、IP、NameNode/DataNode是否运行；换IP后更新endpoint |
| PowerShell不允许执行脚本 | 使用手册中的`powershell -NoProfile -ExecutionPolicy Bypass -File ...`，只作用于该次进程 |
| 模型不如某个基线 | 查看验证集选择和各项测试指标；保留真实结果，不删除不理想成绩 |
